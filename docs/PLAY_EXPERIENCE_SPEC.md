## 1. 목적과 근거

사진 `KakaoTalk_20261115_170734598.jpg`의 메모를 현재 달기지 리와인드 프로젝트에 적용할 개발 요구사항으로 정리한다. 이번 결과물은 명세이며 게임 코드 구현·실행 검증·배포 완료를 뜻하지 않는다. 사진 속 문장은 요구사항 참고 자료로 취급한다.

## 3. 기능 명세

### PE-01 — 자원 게이지

- 전력·산소·식량 각각 이름, 현재 값, 상한, 채워진 막대를 표시한다. 색만으로 자원을 구분하지 않는다.
- 전력 상한은 Simulation.energy_cap(state), 산소·식량 상한은 현재 게임 규칙인 100을 사용한다. 배터리 추가로 충전량이 증가한 것처럼 표시하지 않는다.
- 표시 값은 전달받은 상태의 E/O/F를 사용한다. UI에서 자원을 차감하거나 생산하지 않는다.
- HUD는 확정 상태를 표시한다. 단말기에 기존 미리보기가 연결될 경우 “현재”와 “배치 후 예상”을 구분하며 예상 값을 확정 상태로 덮어쓰지 않는다.
- 막대 비율은 0~1로 제한하고 원래 수치는 숨기지 않는다. 유효하지 않은 상한에서는 빈 막대와 확인 불가 표시를 제공한다.
- 긴 사용 설명은 안내서에 두고 HUD는 짧게 유지한다. 임의 위험 비율을 새 실패 조건처럼 표현하지 않는다.
- 1280×800과 960×600에서 자원 이름·수치가 겹치거나 잘리지 않도록 줄바꿈/세로 배치를 허용한다.

완료 기준:

1. 전력 10/20은 절반, 10/40은 1/4로 보인다. 상한 변경만으로 현재 값 10이 늘지 않는다.
2. 산소·식량 0/50/100이 각각 빈/절반/가득 찬 막대로 보인다.
3. 턴 진행·되감기 후 수치와 막대가 같은 상태로 갱신된다.
4. 게이지 표시 전후 시뮬레이션 결과가 동일하다.

### PE-02 — 내 캐릭터의 팔·다리

- 단순한 우주복 팔·다리를 독립적인 시각 전용 씬으로 만든다. 특정 게임의 자산을 복제하지 않는다.
- 기본 시야에서는 화면 아래쪽에 팔 일부가 보이고, 아래를 보면 다리와 발이 보이도록 한다. 얼굴·머리 내부가 카메라를 가리지 않도록 한다.
- 몸은 플레이어의 수평 회전을 따르고, 팔 연출과 다리 회전을 분리해 위아래를 볼 때 다리가 카메라에 붙어 뒤집히지 않도록 한다.
- 걷기에는 작은 팔다리 움직임, 공중에는 점프 자세, 착지에는 기본 자세 복귀를 적용한다. 큰 카메라 흔들림은 넣지 않는다.
- 시각 메시에는 게임플레이 충돌을 추가하지 않는다. 기존 캡슐 크기·단말기 레이 판정·시설 배치 판정을 유지한다.
- 단말기·안내서·일시정지 상태에서는 동작 애니메이션을 정지하고 UI를 가리지 않는다.

완료 기준:

1. 정면/아래/위, 좌우 회전에서 신체가 과도하게 시야를 가리거나 카메라 내부를 관통하지 않는다.
2. 정지·걷기·점프·착지가 구분되고 멈춘 뒤 걷기 동작이 남지 않는다.
3. 몸 표시 전후 동일 위치에서 단말기를 E로 열 수 있다.
4. 임시 도형으로도 통합 가능하며 최종 모델 교체가 이동 코드 수정을 요구하지 않는다.

### PE-03 — 점프와 중력

- 입력 액션 jump를 추가하고 Space를 연결한다. 탐색 중이며 접지 상태일 때 새로 누른 입력만 점프를 시작한다.
- 공중 재점프와 키를 누르고 있을 때의 자동 반복 점프는 하지 않는다.
- 중력과 점프 높이는 이름 있는 조정 값으로 분리한다. 초안 기본값은 기존 중력 9.8 유지, 목표 높이 0.8 게임 미터, 초기 속도 sqrt(2 × 중력 × 높이)다. 달 중력 재현은 확정 요구가 아니다.
- 기존 수평 이동 속도와 충돌 캡슐을 유지한다. 상승 중 천장 충돌, 하강 중 바닥 착지, 낙하 복귀가 정상 동작해야 한다.
- 단말기·도움말·일시정지 중 Space는 점프를 시작하지 않는다. 복귀 직전에 눌려 있던 키는 놓았다가 다시 눌러야 한다.
- 공중에서 일시정지하면 위치를 유지하고 기존 상태 전환 방식대로 속도를 초기화한다. 재개 시 현재 위치에서 중력을 다시 적용하며 추가 점프를 생성하지 않는다.
- 되감기·낙하 복귀에서는 기존 apply_pose 경로로 위치·회전을 복원하고 속도와 누적 입력을 초기화한다.
- 출입구 단차 문제(UX-030)를 점프 필수 조작으로 덮지 않는다. 기존 보행 재진입 기준은 별도로 유지한다.

완료 기준:

1. 바닥에서 Space 한 번으로 상승→하강→착지하며 공중 Space로 추가 상승하지 않는다.
2. 낮은 천장에 충돌해도 뚫거나 붙어 있지 않고 내려온다.
3. Space를 누른 채 UI를 닫아도 즉시 점프하지 않는다.
4. 점프 중 일시정지·재개, 되감기, 낙하 복귀 후 속도나 입력이 남지 않는다.
5. 30/60/120 FPS 목표 환경에서 점프 높이 차이가 허용 오차 10% 이내인지 측정한다. 측정 불가능한 환경은 미검증으로 기록한다.

### PE-04 — 플레이 중 마우스 고정

- 사용자의 시작/재개 클릭으로 포인터 잠금을 요청한다. 요청 직후 상태만으로 성공이라 간주하지 않고 실제 캡처 상태를 확인한다.
- 캡처된 탐색에서는 커서가 게임 영역 밖으로 이동하지 않으며 마우스 상대 이동으로 시점을 회전한다.
- Esc, 창 포커스 상실, 탐색 중 잠금 상실은 이동·시점 입력을 정지하고 커서를 해제한다. 사용자가 다시 클릭하기 전 자동 재잠금하지 않는다.
- 단말기·안내서·일시정지는 커서를 표시해 버튼을 누를 수 있게 한다.
- 최초 잠금 요청 실패는 시작 화면에 갇히게 하지 않는다. 기존 2초 대기·실패 안내를 유지하면서 “마우스 잠금을 사용할 수 없어 드래그로 둘러봐요”와 함께 드래그 탐색을 추가한다(기존 UX-004의 선택적 대안을 이번 추가 범위로 채택).
- 드래그 탐색은 게임 영역 안에서 시작한 왼쪽 버튼 드래그만 시점을 변경하며 UI 클릭은 소비한다. 버튼 해제·포커스 상실·영역 이탈로 드래그를 종료한다.
- 드래그 대체 모드에서는 브라우저 밖으로 커서가 나갈 수 있다. 완전한 고정은 캡처 성공 상태의 완료 기준이다.
- 잠금 대기/성공/실패와 의도적 해제를 구분한다. 기존의 “캡처가 아니면 매 프레임 pause” 조건을 그대로 적용해 대체 모드를 종료하지 않도록 한다.

완료 기준:

1. 캡처 성공 후 계속 회전해도 커서가 다른 브라우저 영역을 클릭하지 않는다.
2. Esc와 다른 창 전환에서 입력이 멈추고 재개 클릭 후 정상 복귀한다.
3. 잠금 실패 환경에서도 시작·이동·드래그 회전·단말기 열기/닫기가 가능하다.
4. 실패와 재시도 때 화면 전환 반복, 시점 튐, 걸음 입력 고착이 없다.
5. 데스크톱 실행, 일반 브라우저 Web, iframe 삽입 환경을 구분해서 실제 결과를 기록한다. 미실행은 통과 처리하지 않는다.

| 본인 dyhan0528 | A: PE-01 게이지 | feature/PE-01-resource-gauges | 명세 게시 후 독립 착수 가능 |
| 팀원 jsjavsj | B: PE-02 캐릭터 시각 씬 | feature/PE-02-avatar | A와 병렬; 모의 이동 상태로 제작 |
| 팀원 jsjavsj | C: PE-03 점프·중력 | feature/PE-03-jump | B와 파일 독립; 한 사람이 진행할 때 B 다음 C 권장 |
| 본인 dyhan0528 | D: PE-04 마우스 상태 제어 | feature/PE-04-mouse | C와 병렬; player.gd 수정은 통합 단계로 남김 |
| 본인 dyhan0528 | I: PE-05 연결·통합 검증 | feature/PE-05-integration | A~D 완료·소유권 반환 후 착수 |

현실적인 두 사람 흐름: **본인 A / 팀원 B → 본인 D / 팀원 C → 본인 I / 팀원 교차 검증**. A~D의 착수 전 이슈에 기준 SHA와 파일 claim을 기록한다. 상대가 만든 기능은 서로 교차 검증하고, 최종 통합 변경은 jsjavsj가 별도로 검증한다. 배정은 실제 착수나 완료를 의미하지 않는다.

각 기능은 최신 main에서 브랜치를 만들고 Refs로 이슈를 연결한 PR로 인계한다. 독립 컴포넌트 PR의 병합만으로 사용자 기능 완료 이슈를 닫지 않는다. PE-02/04 등 연결이 남은 이슈는 OPEN 유지하고 PE-05에서 실제 수용 기준 통과 후 종료한다. 기존 문서의 통합 규칙대로 main 대상 일반 merge를 사용한다.

처음에 통합 담당이 아래 인터페이스와 파일 소유권을 확정한 뒤 A~D를 동시에 진행한다. 각 작업은 자기 파일만 수정하고 공통 파일 변경 요구는 통합 담당에게 넘긴다. 기존 UX 작업이 같은 파일을 편집 중이면 소유권을 먼저 조정한다.

| 작업 | 독립 작업 범위 | 단독 수정 파일/신규 파일 | 선행 조건 |
| --- | --- | --- | --- |
| A 게이지 | 공용 게이지 컴포넌트, HUD 표시 | 신규 scripts/ui/resource_meter.gd, 필요 시 scenes/ui/resource_meter.tscn; scripts/ui/hud.gd | 자원 표시 계약 |
| B 몸 표현 | 팔·다리 도형/모델, 시각 전용 애니메이션 | 신규 scripts/player/avatar_visual.gd, scenes/player/avatar_visual.tscn, assets/player/ 하위 | 몸 표시 계약; 실제 점프 구현 없이 모의 상태로 진행 가능 |
| C 점프 | 점프 액션·접지·중력·복원 | scripts/player/player.gd, project.godot | 점프 입력 계약 |
| D 마우스 | 잠금 상태 전환·실패·재개 제어 | scripts/world/mission.gd | 입력 모드 계약; player/hud 연동은 모의 객체 또는 변경 요청서로 준비 |
| I 통합 | 씬 장착, 입력 분기, 안내 문구, 단말기 게이지 연결 | scenes/player/player.tscn, C/D 완료 뒤 player.gd, A 완료 뒤 hud.gd, scripts/ui/terminal.gd, scripts/ui/help.gd | 관련 작업 완료 및 소유권 반환 |

인터페이스 제안(아래 이름은 새 계약이며 현재 존재하는 API가 아니다):

- ResourceMeter.set_values(label_text, current_value, maximum_value): 읽기 전용 표시. 전달 상태를 수정하지 않는다.
- AvatarVisual.update_motion(local_velocity, grounded, active, delta): 시각 상태만 갱신한다. 카메라·캐릭터 위치·시뮬레이션을 수정하지 않는다.
- Player.set_look_mode(mode): captured / drag / disabled 중 하나. mission이 모드를 결정하고 player가 입력을 적용한다. D는 호출 측을 준비하고 실제 메서드·드래그 분기는 C 종료 후 I가 추가한다.
- 기존 Player.set_exploring, pose, apply_pose와 HUD.refresh(state), show_mode(mode) 호출은 호환성을 유지한다.
- 마우스 안내 문구와 Space 안내는 A가 hud.gd를 반환한 후 I가 한 번에 반영한다.

의존 관계:

```text
공통 계약 확정
  ├─ A 게이지 ──────────┐
  ├─ B 몸 표현 ─────────┤
  ├─ C 점프 ────────────┼─ I 통합 ─ 통합 검증
  └─ D 마우스 상태 제어 ─┘
```

점프와 마우스 입력 코드를 같은 player.gd에서 동시에 수정하지 않는다. B의 player.tscn 장착도 I가 담당한다. A~D의 독립 제작은 병렬이지만 공통 파일 연결과 최종 검증은 순차로 진행한다. 기존 UX-R01~R06 전체를 병렬로 바꾸라는 의미는 아니다.

## 5. 검증과 인계

- A: 경계 값과 상한 변경을 확인한 이미지 및 상태 입력값.
- B: 정면/아래 시야, 걷기/점프/정지 상태 이미지 또는 영상과 자산 경로.
- C: 접지·공중 입력·천장·일시정지·복원 결과와 사용한 물리 수치.
- D: 환경별 잠금 성공/실패, Esc, 포커스 상실, 재시도 기록.
- I: import/스크립트 검사, 기존 core_contract 및 learning_ui 등 영향받는 검증, 데스크톱·Web 실조작 결과. 기존 테스트를 통과해도 포인터와 시각 검증을 대신하지 않는다.

통합 시나리오: 시작 → 캡처 또는 드래그 탐색 → 걷기와 점프 → 아래를 보며 몸 확인 → E로 단말기 열기 → 시설 배치와 자원 확인 → 턴 진행 → 되감기와 게이지 확인 → Esc → 재개 → 기지 출입 후 단말기 재접근.

현재 A~D 구현과 실제 Player/HUD/단말기 연결 및 구현자 자동·렌더 검사를 완료했다. 환경별 사용자 실조작과 팀원의 최종 교차 검증은 남아 있다. 실제 결과는 PE-05 통합 인계 문서를 참고한다.
