리팩터링에는 규칙을 유지하는 코드 정리, UX 개선, 재현된 결함 수정이 포함됩니다. 아래 검사는 구현 후 수행할 계획이며 이번 문서 작업의 실행 결과가 아닙니다.
### 읽는 법과 우선순위

- `보고/미재현`: 사용자 관찰이며 이번 문서 작업에서 직접 실행 확인하지 않았다. 영문 피드백은 이전 빌드일 가능성이 있으나 현재 빌드와 동일 여부도 미확인이다.
- `미테스트`: 확인하지 못한 항목이다. 결함으로 집계하지 않는다. 보고 당시 브라우저·빌드 SHA가 없고 일부 조작은 마우스 잠금을 흉내 낸 환경이었다.
- P0 후보: UX-004/009/030. 실제 지원 환경에서 진행 불가를 재현하면 최우선, 미재현이면 환경과 남은 확인을 기록한다.
- P1: 사용자 상위 3개 UX-005/015/024와 첫 이해 UX-001/002. P2: 나머지 개선·검증. 낮음: 사용자 지정 UX-010.
- 각 항목의 `규칙 유지`는 v0.1 계산·저장 상태를 바꾸지 않는다는 뜻이다. `별도 결정`은 구현 범위에 자동 포함하지 않는다.

## 2. 화면 흐름과 공통 계약

`시작 → 첫 안내 → 시설 선택/미리보기 → 사건 선택 → 턴 결과 → 복원 후보 → 재도전 또는 성공 요약`

| 단계 | 먼저 보여줄 것 | 다음 행동 |
| --- | --- | --- |
| 시작 | “7턴 동안 기지를 지켜요”, 키보드·마우스 안내, 시작/안내서 | 시작 클릭 및 입력 상태 확인 |
| 첫 안내 | “단말기 가까이 가서 E를 눌러요”, 이동·시선 조작 | 단말기 열기 |
| 시설 | 남은 예산, 시설 카드, 선택 칸, 현재/예상 자원 | 시설 놓기 또는 이번 변경 취소 |
| 사건 | 지금 적용되는 사건, 필수 선택, 지속 기간 | 선택 후 “이번 턴 진행” |
| 결과 | 전력·산소·식량의 생산/소비/최종값, 중단 원인 | 다음 계획 또는 과거 턴 보기 |
| 복원 | 보관된 턴과 후보 근거, 확인할 가정 | 선택한 턴 시작으로 돌아가기 |
| 재도전/성공 | 같은 턴 변화 또는 7턴 완료 요약 | 비교 보기/기지 둘러보기 |

첫 방문에는 현재 단계의 설명 하나를 우선한다. 안내를 다시 볼 수 있고, 이미 아는 사람은 건너뛸 수 있다.
25칸을 숨겨 규칙을 바꾸지 않는다. 되돌리기·비교는 기록이 있을 때 주 동선에 나타내고 기록이 없으면 이유를 설명한다.
안내서의 실제 NASA/CSA 자료와 교육용 게임 규칙을 구분한다. 임무를 실제 7일 또는 실제 생존 예측으로 표현하지 않는다.
모든 미리보기는 snapshot과 draft의 독립 사본을 순수 계산한다. 조회·화면 열기·취소로 자원/성장/사건/보급/attempt_id를 바꾸지 않는다.
사건을 아직 고르지 않았으면 “선택에 따라 달라져요”로 표시하고 선택별 조건을 제시한다. 확정한 동일 입력의 예상값은 실제 결과와 일치해야 한다.
현재값, 배치만 반영한 용량, 턴 실행 후 예상값은 다른 항목이다. 예: `현재 전력 20/20 · 배치 후 용량 40 · 턴 후 예상 별도`.
범위 밖: 새 시설·새 재화·모델 재제작·모바일 게임·강제 순간이동·신규 월드 임무. 검토 초안을 구현 승인으로 취급하지 않는다.

## 3. 백로그별 수용 명세

### UX-001 — 단계가 보이는 단말기 · P1 · 규칙 유지
- 관찰/상태: 25칸·시설·되감기·비교가 동시에 보여 부담스럽다는 보고/미재현.
- 목표: 현재 할 일 하나와 핵심 조작을 우선하고 상세 설명·비교는 필요할 때 연다.
- 수용: 첫 방문에 목표/다음 행동이 보이며 시설→사건→결과 순서가 명확하다. 기록 없는 비교는 설명 없이 빈 패널로 남지 않는다.
- 검사: 새 세션부터 T2까지 화면별 주 행동을 기록하고 안내 건너뛰기/다시보기와 기존 배치 기능 접근을 확인한다.

### UX-002 — 어린이가 이해하는 안내 · P1 · 규칙 유지
- 관찰/상태: 대상 7~12세가 내용을 이해하기 어렵다는 의견/미재현.
- 목표: 한 안내에 한 행동, 짧은 한국어와 의미 있는 그림을 함께 사용한다.
- 수용: “전력을 아껴요”, “이번 변경 취소”처럼 동작을 말하며 색만으로 의미를 구분하지 않는다. 핵심 용어는 화면 간 동일하다.
- 검사: 문구 검수 후 대상 연령 사용자에게 다음 행동/자원 의미를 설명하게 하고 이해 여부를 기록한다. 관찰 전 이해도 달성을 주장하지 않는다.

### UX-003 — 선택의 성취감 · P2 · 규칙 유지, 보상 재화는 별도 결정
- 관찰/상태: 재미와 참여감이 약하다는 의견/미재현.
- 목표: 선택 직후 시각 피드백, 턴 목표 달성 문구, 마지막에 자신이 바꾼 선택 요약을 제공한다.
- 수용: 시설 선택/배치/턴 완료가 서로 구분되고 요약은 실제 기록에 근거한다. 과장된 점수·새 재화를 지급하지 않는다.
- 검사: 정상·실패·재도전 흐름에서 피드백을 확인하고 연출 중 중복 확정이나 조작 차단이 없는지 확인한다.

### UX-004 — 마우스 잠금 실패 복구 · P0 후보 · 규칙 유지, 입력 방식 설계 검토
- 관찰/상태: WrongDocumentError와 시작 정지 보고/미재현. iframe·Esc 재잠금 영향과 일반 Chrome 정상 여부도 확인 필요.
- 목표: 실패 이유/재시도를 알리고 잠금 불가 환경에서도 가능한 대체 조작을 검토한다.
- 수용: 정상 잠금은 기존 조작을 유지한다. 실패는 무한 시작 화면 대신 안내하며 드래그 시점 대안을 채택하면 해당 모드에서 이동·단말기까지 완료 가능해야 한다.
- 검사: 표시된 브라우저에서 직접 클릭, 잠금 거부, Esc 후 재시도, 포커스 복귀, iframe을 각각 기록한다. 대체 입력은 capture 상실 시 pause 처리와 충돌하지 않아야 한다.

### UX-005 — 성공과 중단의 구분 · P1/사용자 상위 3 · 규칙 유지
- 관찰/상태: 두 결과가 회색 버튼으로 유사하고 성공 후 시작 인트로 재등장 보고/미재현.
- 목표: 중단은 원인과 재시도, 성공은 축하와 실제 선택 요약을 보여준다.
- 수용: 실패 턴·원인 자원 또는 안전 조건이 보인다. 성공에는 “7턴 훈련 완료!”와 요약이 있고, 닫아도 완료 상태를 유지한다. 새 게임만 명시적 별도 행동이다.
- 검사: 전력/생명유지/안전 중단과 성공 각각에서 닫기·열기·되돌리기를 확인한다. 보상 재화·별도 성장 시스템은 추가하지 않는다.

### UX-006 — 산소 생산과 소비 · P2 · 표시 규칙 유지, 밸런스 별도 결정
- 관찰/상태: 소비6인데 산소가 증가하며 내역이 없다는 보고/미재현. `8-6=+2`는 v0.1 정상 규칙이다.
- 목표: 전력과 함께 산소 생산·소비·순변화·최종값을 표시한다.
- 수용: 일반 턴은 “산소 생산 8 / 소비 6 / 변화 +2”, 상한 도달 시 실제 증가량을 구분한다. 실패로 생략된 계산은 미계산이다.
- 검사: 일반 턴·상한100·전력 실패의 표시와 결과를 대조한다. 긴장감 개선을 이유로 생산/소비값을 변경하지 않는다.

### UX-007 — 효과 지속 기간 · P2 · 규칙 유지
- 관찰/상태: T2 선택이 T3까지 지속되는데 T3 설명이 없다는 보고/미재현.
- 목표: 고장과 선택 효과가 언제까지 적용되는지 항상 알린다.
- 수용: T2 “발전 중단: 이번 턴과 다음 턴”, T3 “이번 턴까지 적용”; 절약 시 재배 정지/성장 멈춤을 표시한다.
- 검사: normal/conserve 각각 T2→T3→T4를 진행하고 복원 후 모드·종료 시점이 실제 상태와 일치하는지 확인한다.

### UX-008 — 배치 미리보기 · P2 · 규칙 유지
- 관찰/상태: 배터리 추가/제거 후 현재 전력 표시가 그대로라는 보고/미재현.
- 목표: 현재 전력과 편집한 저장 용량, 턴 결과 예상치를 구분한다. 배터리는 전력을 생성하지 않는다.
- 수용: 추가는 cap +20, 제거는 확정 시 cap 제한을 예상 표시한다. 취소 시 예상값을 지우고 확정 전 실제 E/cap은 유지한다.
- 검사: E20/cap20 추가, E28/cap40 제거, 취소, 미선택 사건을 확인하고 조회 전후 실제 snapshot 동등성을 검사한다.

### UX-009 — 단말기 재접근 · P0 후보 · 규칙 유지
- 관찰/상태: 이동 후 충돌에 막히고 E 안내가 없다는 보고/미재현. 자동 입력 영향 가능성도 보고됐다.
- 목표: 유효한 통로로 돌아와 계약 거리2m 이내에서 단말기를 열 수 있다.
- 수용: 가까우면 E 안내와 열기 동작이 일치하고 정상 접근로가 막히지 않는다. 거리 확대나 순간이동으로 우회하지 않는다.
- 검사: 직접 이동으로 정면/측면/멀리서 돌아오기, 시설 배치/복원 후 접근을 확인하고 좌표·거리·충돌체를 기록한다. UX-030과 원인을 별도로 판정한다.

### UX-010 — 저장과 이어하기 · 낮음/사용자 지정 · 별도 결정
- 관찰/상태: 새로고침 시 T1부터 시작한다는 보고/미재현. 현재 저장 미제공 자체를 회귀 결함으로 단정하지 않는다.
- 목표: 우선 새로고침 시 진행 손실 안내를 검토한다. 저장 도입은 후속 선택이다.
- 수용: 도입 결정 전 자동 저장을 약속하지 않는다. 채택 시 규칙 버전·시나리오·snapshot·분기 복원 범위와 삭제/손상 처리를 먼저 확정한다.
- 검사: 현재 새로고침 동작 확인; 저장 채택 후에만 정상 이어하기/손상 데이터/버전 불일치/중복 보급 검사를 추가한다.

### UX-011 — 깨지지 않는 문자 · P2 · 규칙 유지
- 관찰/상태: NORTH/턴 버튼 기호가 네모로 보인다는 보고/미재현.
- 목표: 사용 글리프를 확인하고 지원 폰트 또는 기존 아이콘으로 읽을 수 있게 한다.
- 수용: 한국어·영문·방향·버튼 기호가 모두 표시되며 아이콘만 있는 조작에는 의미를 알 수 있는 문구가 있다.
- 검사: 실제 Web 출력에서 폰트 로딩 후 해당 화면을 양 언어로 캡처한다. 새 폰트 도입은 사용조건과 용량 검토 후 결정한다.

### UX-012 — 창 크기에 맞는 배치 · P2 · 규칙 유지
- 관찰/상태: 검은 띠·좁은 창의 작은 글씨 보고/미재현. stretch expand는 제안이지 확정 해법이 아니다.
- 목표: 주요 문구와 조작이 잘리지 않고 읽을 수 있도록 패널 재배치/스크롤을 검토한다.
- 수용: 아래 환경 행렬에서 주 행동·선택지·닫기 버튼을 가리지 않는다. 단순 전체 축소 대신 정보 순서를 유지한다.
- 검사: 실제 viewport와 DPR을 기록하고 크기 변경 중 입력 좌표/팝업/3D 대응을 확인한다. 미지원 최소 크기는 안내한다.

### UX-013 — 행동 가까운 알림 · P2 · 규칙 유지
- 관찰/상태: 토큰 부족 알림이 화면 아래에 작게 남는다는 보고/미재현.
- 목표: 현재 단말기 행동 옆에 이유를 제공하고 낡은 상태 메시지를 정리한다.
- 수용: “예산이 2개 부족해요”가 해당 시설 근처에 보인다. 선택 변경/조건 해소 시 오래된 오류가 사라지고 필수 오류는 해결 전 확인 가능하다.
- 검사: 예산 부족→선택 변경→취소→재선택을 반복해 잘못된 잔류·순간 소멸·겹침이 없는지 확인한다.

### UX-014 — 사용할 수 없는 이유 · P2 · 규칙 유지
- 관찰/상태: 구매 불가 시설이 활성처럼 보이고 T2 진행 불가 이유가 없다는 보고/미재현.

## 6. 수용 환경과 실행 순서

다음은 **구현 후 수행할 검사 계획**이다. 이번 문서 작성에서는 게임·브라우저·서버 검사를 수행하지 않았다.

| 환경/경로 | 최소 확인 | 기록할 증거 |
| --- | --- | --- |
| Windows 직접 실행 | 정상7턴, 3종 중단, 복원·동일 턴 비교 | 실행 버전/커밋, 선택/수치/화면 |
| Windows Chrome·Edge 일반 탭 | 시작·입력·Esc·안내서·완료 후 복귀 | OS/브라우저 버전, 빌드 SHA, 포인터 상태 |
| 실제 삽입 환경이 있으면 iframe | 잠금 거부/재잠금/대체 입력 | URL/삽입 조건/오류, 미지원 여부 |
| 1920×1080·1280×720·1024×768·800×900 | 첫 안내/시설/사건/결과/복원 가독성 | viewport/DPR/배율100%, 잘림·최소 크기 |

| 직접 보행 | 단말기 재접근·출입구 왕복·복원 후 재접근 | 위치/경로/충돌·거리, 재현 유무 |

1. 최신 실행 빌드와 보고 환경부터 맞추고 UX-004/009/030을 직접 재현한다. 원인 확인 전 해결 방식이나 해결 완료를 확정하지 않는다.
2. UX-001/002의 단계 구조와 UX-005/015/024의 핵심 화면을 확정한다. 모델 담당 jsjavsj의 원본은 이 작업에서 수정하지 않는다.
3. UX-006~008/013~017/021/023/025의 표시·예상 계산·비교를 연결하고 v0.1 정상/실패/복원 예시를 회귀 확인한다.
4. 화면 크기·폰트·로딩·지도 대응·이동 안내와 UX-028/029 미테스트를 확인한다. 별도 결정 후보는 채택된 것만 작업으로 전환한다.
5. 독립 Verifier가 변경 snapshot과 위 행렬의 결과를 확인한다. 대상 연령 이해도는 실제 관찰 전 미검증으로 남긴다.
